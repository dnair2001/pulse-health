# Privacy and data retention

Pulse Health is a **demo**. This document describes what actually happens to data in this
repo today; it is not a compliance policy and should not be read as one. See [SECURITY.md](../SECURITY.md#out-of-scope)
for the properties of a mock backend that are intentional rather than gaps.

## No real PHI

Nothing in this repo handles real patient data. Providers, patients, slots and appointments are
all synthetic, generated by `apps/mock-api/app/seed.py` relative to the current time so the demo
always has plausible upcoming/past appointments. Names, specialties and reasons for visit are
fictional placeholders, not sampled from or derived from any real person.

Do not put real personal or health information into this system. There is no control that would
protect it if you did.

## Storage and reset

- All state lives in `apps/mock-api/data/store.json`, a gitignored JSON file written on every
  mutation (see `docs/api-contract.md`).
- `POST /api/dev/reset` deletes and rebuilds that file from the seed data, discarding whatever was
  there. It requires no credential and can be called by anyone who can reach the API — see
  SECURITY.md's out-of-scope list.
- There is no backup, export, or long-term archive of this data. Restarting from a clean
  checkout or calling `/api/dev/reset` is the only "retention" this project has.

## Logs

- Structured JSON logs go to stdout and to `apps/mock-api/data/logs/api.log`; OpenTelemetry
  traces go to `apps/mock-api/data/logs/traces.jsonl`. Both are local files under `.gitignore`,
  written by the process that generated them, and are never shipped to an external log
  aggregator, SIEM, or third party.
- Because everything is local-only and the data is synthetic, there is no retention policy
  beyond "the file exists until someone deletes it or the container is torn down."
- What is and is not logged — including the field-name scrubber applied to log records and why
  `POST /api/telemetry`'s `message` field is bounded to code-controlled values like
  `error.name` rather than raw exception text — is described in AGENTS.md's telemetry section,
  under `apps/mock-api/app/observability/` conventions. That description is authoritative;
  this file only points at it.

## Metrics

`GET /metrics` exposes Prometheus counters and histograms (`app/observability/metrics.py`).
Labels are closed enums (HTTP method/route template/status, telemetry `source`/`level`,
appointment `status`) chosen specifically so a concrete patient, appointment id, or free-text
value can never become a label. Nothing scraped from `/metrics` carries data that identifies an
individual, real or synthetic.
